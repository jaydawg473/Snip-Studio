SCOPE AND LIMITATIONS
Tests use generated images, pure typed values, fake providers, metadata/call
inspection and unshown controls. They do not run the app entrypoint, capture
the user's desktop, inject input, read or change Windows settings, register
native hotkeys, or load/save personal preferences. Rendering can create hidden
child-control handles; the form itself is not shown. Actual screen sampling,
physical/mixed-DPI transitions, keyboard priority, displayed native focus and
installed upgrades remain unverified.

The temporary screen sampler is owned/modal, undimmed and pixel-based. Its
snapshot stays in memory, bypasses capture policies/auto-save/OCR/clipboard,
and is disposed on completion or cancellation. Gaps between monitors reject
sampling. Shape opacity and the document remain unchanged until Apply.

PRINT SCREEN
Microsoft documents that overriding Windows' default Print Screen assignment
can depend on the application being in the foreground. Registration alone is
therefore not treated as a guarantee of background capture. The program reads
Windows' assignment state only after showing/refreshing the UI, handles absent
and unreadable values honestly, opens the supported Windows Settings page,
and retries registration after return or Retry. It does not write Windows
preferences or install a low-level keyboard hook. The Windows capture option
must be turned off by the user for the intended background shortcut setup.
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey
